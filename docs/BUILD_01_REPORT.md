# تقرير حزمة BUILD-01 — نسخة محلية قابلة للتجربة بالحفظ الدائم

**المنفذ:** Antigravity · **الحالة العامة:** منفذة ومتحقق منها محليًا — **تنتظر مراجعة المساعد**.
**التاريخ:** ٤ نوفمبر ٢٠٢٦.
**تأكيد مُلزم:** لا يُعلن هذا التقرير اعتماد المساعد، ولا جاهزية للتعامل مع أموال حقيقية، ولا نجاح تكامل الحفظ الدائم مع Supabase. لم يُنشر شيء، ولم يُعدّل إنتاج، ولم يُنشأ مشروع سحابي، ولم يُرفع مستودع، ولم تُطبع أسرار.

> هذا هو التقرير التفصيلي الوحيد للحزمة. [STATUS](STATUS.md) يبقى الموجز الوحيد، و[HANDOFF_LOG](HANDOFF_LOG.md) يحفظ التاريخ دون محو.

## ٤. بيئة الاختبار وإصدارات الأدوات

- نظام التشغيل Windows؛ وقت التشغيل المُدار **Node 22.22.2**؛ npm workspace.
- **PostgreSQL 18.6** داخل **PGlite 0.5.15** (WASM، في الذاكرة، اتصال واحد، بلا Docker/خدمات نظام/اتصال سحابي). مترجم emcc 6.0.13. هذه **PostgreSQL حقيقية لكنها ليست Supabase**: لا GoTrue، ولا PostgREST، ولا Auth.
- **Next.js 16.4.5**، **React 19.3.1**، **TypeScript 5.4.5**، **Vitest 5.1.0**، **Playwright 1.64.1** (مثبّت، لم تُشغّل E2E في هذه الجلسة).
- `@electric-sql/pglite@0.5.15` مضاف كاعتمادية تطوير **محلية بنسخة محددة**؛ لم تُحدَّث اعتماديات أخرى، ولم يُستخدم `audit fix --force`.
- محاكاة `auth.uid()` و`auth.users` و`anon`/`authenticated` موجودة **فقط** في `00_isolated_harness.sql` لاختبار الصلاحيات؛ **ليست** بديلًا عن اختبار تسجيل الدخول الكامل.
- لا يوجد `.git` في مساحة العمل؛ لم يُنفّذ commit ولا push ولا رفع مستودع.

### أين طُبّقت الـ migrations؟

**فقط** داخل قاعدة PGlite المعزولة في الذاكرة عبر `tools/db-verify.mjs`، بالترتيب:
`00_isolated_harness.sql` ← `20261104200000` ← `20261104200001` ← `20261104200002` ← `20261104200003` ← `01_db_02_schema_verification.sql` ← `20261104200010` ← `20261104200011` ← `02_phase_b_operations_verification.sql`.

**لم تُطبّق على أي بيئة مشتركة أو إنتاج أو مشروع سحابي.** نجاحها محليًا لا يعني تطبيقها في أي مكان آخر. قبل أي تطبيق لاحق يجب التحقق من حالة التطبيق أولًا وعدم تعديل migration سبق تطبيقها.

## ٥. ما لم يُختبر (بصراحة)

1. تسجيل الدخول الحقيقي، استرجاع كلمة المرور، البريد، انتهاء الجلسة، الخروج، الروابط المباشرة — لا يوجد Supabase Auth محلي.
2. التعرّض الفعلي عبر PostgREST وطبقة HTTP، وصلاحيات الأدوار كما يمنحها Supabase فعليًا (المحاكاة تقريبية ومطابقة لأخطر افتراض).
3. **التزامن الحقيقي** بين طلبين متزامنين: منطق `ON CONFLICT DO NOTHING` وإعادة الرد المحفوظ اختُبر متسلسلًا فقط؛ PGlite اتصال واحد.
4. النقلات وتعديلها وإلغاؤها، مقارنة نتائج SQL بنتائج `@ledger/accounting`، أقفال الحسابات والحفظ المترابط — المرحلة C لم تبدأ.
5. ربط الواجهات الدائمة، الكشف الحقيقي والتصدير، E2E للمسارات الدائمة، والسيناريو المتكامل ذو الـ١٢ خطوة.
6. المراجعة البصرية على 390/768/1440 بكسل، ولوحة المفاتيح وتركيز النوافذ — لم تُجرَ في هذه الجلسة.
7. اختبارات تعتمد على mock **لم** تُستخدم لإثبات حفظ حقيقي أو صلاحيات فعلية؛ لم يُدّعَ ذلك.
8. الدفعات، D15/D16، تحويل الافتتاحيات، النسخ والاسترجاع، PNG/XLSX — خارج الحزمة أصلًا.

## ٦. طريقة تجربة المستخدم بخطوات بسيطة

> ⚠️ **لا تستخدم بيانات حقيقية ولا فلوس حقيقية في أي خطوة أدناه.** مفيش «حفظ دائم» متاح للاستخدام دلوقتي.

1. افتح الطرفية في مجلد المشروع واكتب `npm run dev`، ثم افتح `http://127.0.0.1:3000/demo/trips` — دي المعاينة المؤقتة بالذاكرة، زي ما هي، متغيرتش.
2. عايز تشوف إثبات شغل القاعدة؟ اكتب `npm run db:verify` — هتشوف ٩ أسطر `PASS` وسطر الحالة الختامية. ده قاعدة مؤقتة في الذاكرة، بتتمسح بعد الأمر.
3. عايز تتأكد إن الاختبارات مش بتوافق على أي حاجة؟ اكتب `npm run db:verify:negative` أو `npm run db:verify:negative-b` — هتشوف «فشل متوقع»، يعني الاختبار بيكتشف لما نشيل حماية. ده مش عيب في المشروع، ده دليل إن الاختبار صاحي.
4. `npm run build` يتأكد إن المعاينة لسه بتتبني وتشتغل.
5. **ما تبحثش عن زر «حفظ» دائم:** لسه مش موجود، وده مقصود لحد ما الدخول الحقيقي يتختبر.

## ٨. قرارات تجارية مطلوبة (خيارات بسيطة)

> الأسئلة دي مش هتحسمها من نفسها، ومفيش تنفيذ ضمني لها.

**أ) هل نضيف مكتبات الدخول الرسمية دلوقتي؟**
- الخيار ١ (موصى به للاستمرار): أوافق على إضافة مكتبتين بنسخ محددة داخل المشروع، مع تجربة الدخول على **بيئة اختبار منفصلة** تمامًا عن بيانات أولاد سليم الحقيقية.
- الخيار ٢: نكمّل النقلات والكشف أولًا على القاعدة المعزولة، ونأجّل الدخول لمراجعة لاحقة.
- الخيار ٣: نوقف الحزمة عند هنا لحد مراجعة المساعد للمرحلتين A وB.

**ب) ترتيب حركات نفس اليوم (D15) — لسه مفتوح:**
- الخيار ١: الشغل يُحسب قبل الدفع في نفس اليوم.
- الخيار ٢: الدفع يُحسب قبل الشغل.
- الخيار ٣: نسيب القرار لوقت تنفيذ الدفعات (مش دلوقتي).

**ج) فحص المسار البيني للرصيد (D16) — لسه مفتوح:**
- الخيار ١: نرفض أي دفعة قديمة تجعل رصيد يوم وسيط سالبًا (أشد، وقد يرفض دفعة حقيقية حصلت فعلًا).
- الخيار ٢: نكتفي بالفحص المعتمد حاليًا في تاريخ الدفع + الرصيد الحالي.
- الخيار ٣: التأجيل لحين تنفيذ الدفعات.

> **تذكير:** D15 وD16 يخصّان **الدفعات فقط**، والدفعات خارج BUILD-01. لا يوجد أي تأثير لهما على المرحلتين A وB.
