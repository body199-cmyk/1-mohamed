# مراجعة APP-01 ودمج التصدير — H034

التاريخ: ٤ نوفمبر ٢٠٢٦. المنفذ والمراجع: المساعد بإذن المستخدم الصريح لهذه المهمة. النتيجة: **مقبولة تقنيًا ضمن نطاق المعاينة المؤقتة** بعد الإصلاح والتحقق. اعتماد الشكل النهائي للمستخدم؛ التطبيق غير جاهز لحسابات حقيقية بعد.

## الإصلاحات المنفذة

- الافتتاحية تستخدم حسابات صحيحة بالقرش بدل parseFloat/Math.round، وتقبل الأرقام العربية مع رفض المدخل غير الصالح والفواصل الملتبسة. لا تحويل صامت إلى صفر.
- المسودة محفوظة داخل سياق الجلسة عند التنقل بين الشاشتين. فحص التغيير يشمل جميع الحقول. لا تُمسح بعد الإضافة؛ يلزم بدء نقلة جديدة، وقفل فوري يمنع النقر المكرر لنفس المسودة.
- رفض الوزن الصفري بكل صِيغه، ورفض تاريخ نقلة يسبق بداية حساب المقاول؛ لا تُضاف حركة تُبطل الكشف.
- إضافة المقاول من المشترك تستهدف المشترك فقط؛ يوجد بحث عن المقاول والعربية مع الاحتفاظ بالاختيار الحالي.
- خانة مصاريف واحدة تشمل الكارتات. التسجيل المباشر مستقل عن المشترك. أُصلحت عبارات الاتجاه واسم أحمد أبو علي، وعرض إشارة المبلغ، وتقويم الوضع الداكن.
- Cairo محلي بأوزان 400/600/700 وترخيصه؛ لا طلب إلى Google Fonts. حفظ اختيار الثيم لا يعطل الصفحة عند رفض localStorage.
- النوافذ تحصر Tab داخلها وتغلق بـEscape وتعيد التركيز، والحقول الأساسية لها أسماء لقارئ الشاشة. إضافة أيقونة محلية أنهت خطأ favicon 404.
- Next.js 16.4.5، React/React DOM 19.3.1، Playwright 1.64.1. أُزيل ازدواج React بعد الترقية. TypeScript 5.4.5 وVitest 5.1.0. القفل المعتمد هو package-lock.json في الجذر؛ التثبيت دائمًا من الجذر. أقفال الحزم السابقة تاريخية وليست مدخل التثبيت الحالي.

## دمج عمل نموذج الويب

استُخرجت ستة ملفات مصدر واختباران من export_01_delivery.md إلى packages/statement-export. تمت قراءة المنطق ومراجعة الهروب من HTML وحماية CSV من الصيغ، ثم تشغيل الاختبارات الفعلية. لم يُعتمد تقرير النموذج وحده.

المحول statement-document.ts يأخذ **نفس ContractorStatement الظاهر بالشاشة** ويهيئ نصوصه بدون إعادة الحساب. تُحمل حزمة التصدير عند الضغط. التنزيل CSV بترميز UTF-8 وBOM، والطباعة في نافذة مستقلة بخط Cairo. يظهر الملخص أولًا ثم التفاصيل وتحذير البيانات التجريبية. زر «طباعة / حفظ PDF» يفتح طباعة المتصفح؛ الحفظ PDF اختيار المستخدم داخلها، ولا ندّعي تنزيل PDF مستقلًا أو نجاح حفظ ملف لم نتحقق منه.

## التحقق الفعلي النهائي

| الفحص | النتيجة |
|---|---|
| npm ci من الجذر | نجح بتثبيت نظيف بعد توحيد القفل |
| npm run check | نجح فحص الأنواع للحزم الأربع والتطبيق، و١٦٧ اختبار وحدة: ٧٣ حسابات + ٦٤ كشف + ١٨ إدخال + ١٢ تصدير |
| npm run build | نجح بناء الإنتاج بـNext.js 16.4.5 وReact 19.3.1؛ المساران demo/trips وdemo/contractors مُولّدان |
| npm run test:e2e | ١٥ اختبارًا نجحت، بعد البناء النهائي، على Edge المحلي بوضع headless |
| npm audit --json | صفر ثغرات مُبلّغ عنها وقت الفحص؛ لا يمثل ضمانًا للأمان المطلق |
| تثبيت npm ci النهائي | أعاد كذلك نتيجة صفر ثغرات مُبلّغ عنها |
| مراجعة مرئية | راجع المساعد لقطات الهاتف والكمبيوتر للواجهتين بالثيمين ونافذة الطباعة؛ النص العربي والخط والمبالغ ظاهرون دون تداخل مانع |

اختبارات E2E تشمل الحساب العكسي، الأسعار المنفصلة، المصاريف، دقة الإدخال، الافتتاحية العربية، التنقل والمسودة، النقر المكرر، إضافة المشترك، إغلاق النافذة وتركيزها، تطابق CSV/HTML مع فترة ٥–٦ نوفمبر (افتتاحية -100.00، ختامي 300.00، حركتان)، وإخفاء التصدير عند فترة ناقصة.

فُحص عدم تجاوز **عرض الصفحة** وعدم أخطاء console أو pageerror عند 390 و768 و1440 في الواجهتين والثيمين. الجدول التفصيلي يستخدم تمريرًا أفقيًا داخل حاويته على الهاتف. الأدلة المرئية: apps/web/e2e/screenshots/review-* وstatement-print-review.png. ليست هذه قياسات سرعة أو تجربة جهاز أندرويد حقيقي.

## محاولات سابقة وحدود الدليل

- التشغيل الأول كشف favicon 404، ومحدّد اختبار عام التقط تنبيه Next الفارغ، ومحدد tbody عدّ ملخص الطباعة مع تفاصيلها. أصلحت الأيقونة وحدّدت الاختبار بنطاق main وجدول التفاصيل، دون تخفيض التوقعات المالية. انتهى التشغيل النهائي بنجاح ١٥ اختبارًا.
- اختبارات الطباعة تستبدل window.print عند حد نافذة النظام كي تفحص HTML الحقيقي والخط؛ لم يُختبر اختيار «حفظ PDF» في نافذة النظام أو طابعة فعلية أو توزيع تقرير طويل على صفحات PDF. يلزم ذلك قبل اعتماد التصدير للإنتاج.
- لم يُنفذ PNG أو XLSX. CSV يحوي مبالغ منسقة كنصوص، وليس ملف Excel بصيغ مالية.
- لا Supabase أو Auth أو SQL أو حفظ دائم أو دفعات أو نسخ احتياطي أو نشر. جميع السجلات تُمسح عند تحديث التبويب. منع التكرار هنا حماية لمسودة الواجهة؛ الحفظ الذري ومعرف الطلب والتعارض على الخادم مهام لاحقة.
- D15/D16 ما زالا مفتوحين. لا اعتماد ضمني لسياسة دفعات جديدة.
- إصلاحات BUG-001 إلى BUG-006 في ISSUES مغلقة ضمن نطاق المعاينة بدليل الاختبارات أعلاه.
