## 8) نموذج التطوير الموازي الآمن

**المبدأ الواحد: `main` على GitHub هو المصدر الموثَّق الوحيد.**

| الحرف | القاعدة |
|---|---|
| A | OpenCode يعمل دائمًا على فرع محلي `opencode/<اسم>` (بدأنا بـ `opencode/local-work`) |
| B | التطوير الأونلاين على فروع `feat/<h-id>-...` (كمثال حي: `feat/h063...` الموجودة الآن في المستودع) |
| C | أي دمج إلى `main` عبر PR مُراجَع ومُختبَر فقط — بلا دمج مباشر وبلا `--force` |
| D | قبل شغل ملف مشترك: `git fetch origin` ثم `git log origin/main -- <الملف>` للتأكد أن أحدًا ما عدّله |
| E | قبل كل جلسة: `git fetch origin` ثم مراجعة `git log HEAD..origin/main --oneline` — وإن وُجد جديد، `git rebase origin/main` على فرعك المحلي |
| F | ممنوع دائمًا: `git reset --hard`، `git clean`، `push --force`، وأي كتابة فوق نسخة أحدث بغير مراجعة |
| G | التعارضات تُحل بمراجعة صريحة، وسجل كل قرار في HANDOFF/تقرير مختصر |
| H | `main` لا تُعدَّل محليًا مطلقًا بغير استرجاع merge من PR مُعتمد |

**إجراء المزامنة المستقبلية خطوة بخطوة:**

```bash
cd مجلد الكلون النظيف على اللابتوب (المسار المحلي محجوب من النسخة العامة)
git switch opencode/local-work     # أو أي فرع opencode آخر
git fetch origin
git log HEAD..origin/main --oneline   # اقرا الجديد قبل أي حركة
git rebase origin/main                # بعد التأكد إن فرعك غير مضروب على السيرفر
# اختياري: git pull --ff-only origin main من فرع main المحلي لمواءمته بلا تعارض
```

للمزامنة المعاكسة (إرسال شغل من اللابتوب إلى GitHub — تحتاج إذنك أولًا): من فرع OpenCode الجاهز بعد الاختبار، يُركب `git push origin opencode/<اسم-الفرع>` — ثم على GitHub يُفتح PR (من `opencode/<...>` أو `feat/<...>` إلى `main`) ← مراجعة ← اختبارات ← إدماج موثق. أي دفع لا يحدث بلا إذن صريح من المالك ببيان الفرع والهدف.

## 9) البنود المتبقية تحتاج إذن صريح من المستخدم (لا تنفيذ تلقائي)

1. **تصفية آثار اختبار E2E** في الكلون: استرجاع الـ24 صورة PNG المعدَّلة، أو الإبقاء عليها مع تسجيلها — قرارك (استرجاعها يلزمه إذن لأنه أمر استرجاعي).
2. **تحديث `review-regressions.spec.ts`** ليتوقع صيغة H063 (+/- في مبالغ CSV) — قرار اعتماد لأن H063 سلوك معتمد أونلاين؛ لا إصلاح تلقائي.
3. **إعادة تشغيل `forms-h057`** في ظروف بيئية أفضل أو وقت مناسب (فشل بيئي واحد فقط).
4. **إصلاح regression التباين H059** في الثيم الداكن على فرع أونلاين جديد — خارج نطاق هذا التقرير.
5. **أي `git push`** — من الكلون أو من الأصل — فقط بعد إذن صريح ببيان الفرع والهدف.
6. **تعيين الكلون كمساحة عمل OpenCode الحالية** وتجميد استخدام الأصل — قرارك؛ المقارنة أثبتت أن الأصل لا يحمل أي شغل فريد.
7. **هل تبقى النسخة الأصلية القديمة مرجعًا تاريخيًا كما هي، أم يُوحَّد المسار لاحقًا على مستودع واحد؟** — قرار لك.
8. إن توسّع الشغل مستقبلًا خارج قناة msedge الحالية، سيُطلب تثبيت متصفح Playwright إضافي — لا يُثبَّت إلا بإذن صريح.
