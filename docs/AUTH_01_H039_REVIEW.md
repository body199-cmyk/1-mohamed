# AUTH-01 / H039 — تمهيد حراسة المسارات الدائمة (fail-closed)

**التاريخ:** ٥ نوفمبر ٢٠٢٦. **الفرع:** `feat/auth01-safe-boundary-h039`. **الحالة:** كود أولي ومراجعة مطلوبان قبل الدمج؛ **هذه ليست مصادقة حقيقية ولا فتحًا للحفظ الدائم**.

## نقطة الانطلاق الصحيحة

- أُغلق [PR #1](https://github.com/body199-cmyk/1-mohamed/pull/1) بدمج ناجح: `cf96b0c5f3acb2bc7d7a6732d67d5c504df15bd5` على `main`. نتيجة H038 النهائية: GitHub Actions run `41943012378`، ١٦٧ اختبار وحدة، ١٦ خطوة SQL، ٣ أدوات تحكم سلبي، وبناء ناجح. لا يحسم ذلك Auth الحقيقي.
- `AUTH-01` في `SUBTASKS` يحتاج `@supabase/ssr` و`@supabase/supabase-js` ومشروع اختبار مع GoTrue/PostgREST؛ لا يوجد في المستودع بعد ما يثبت نجاحهما، ولا صرح المستخدم ببيانات مفاتيح/نشر.
- التوثيق الرسمي المراجع: [Supabase SSR Next.js](https://supabase.com/docs/guides/auth/server-side/creating-a-client?framework=nextjs&package-manager=npm) و[Next.js 16 proxy.ts](https://nextjs.org/docs/app/api-reference/file-conventions/proxy)؛ `proxy.ts` في Next16 وليس `middleware.ts`، وحماية الهوية على الخادم لاحقًا بـ`getClaims()` ثم فحص المالك وليس `getSession()`.

## نطاق H039 الصغير (AUTH-01/PREP)

1. `apps/web/src/proxy.ts`: حراسة مؤقتة **تمنع أي مسار غير مصرح كصفحة عامة** حتى تركيب مصادقة حقيقية، بما في ذلك مسارات جديدة لم تُذكر بالاسم؛ يُسمح فقط بـ`/` و`/login` و`/demo/*` والأصول الثابتة اللازمة. GET/HEAD لمسار غير عام يعيد 307 لـ`/login?next=<path>`، أما POST وسائر الكتابات (حتى على صفحات demo) فترفض 503 دون إعادة توجيه الجسم. `cache-control: no-store`.
2. `apps/web/src/app/login/page.tsx`: صفحة معلومات واضحة، **بدون نموذج كلمات مرور**؛ لا تعطي انطباعًا أن تسجيل الدخول يعمل، وتربط المستخدم بمعاينة `/demo/trips`.
3. `tools/auth-boundary-smoke.mjs`: اختبار HTTP حقيقي مع سيرفر Next مبني، يتحقق من سلامة المعاينة والـlogin، و١٢ مسار GET محميًا وستة POST مرفوضة، مع أصول عامة. لا يحتاج Supabase أو أي اتصال خارجي.
4. إضافة خطوة HTTP إلى `.github/workflows/verify.yml` بعد `npm run build`، دون تغيير اختبارات A/B/C أو شروطها.

**معيار القبول:** `npm ci` + `npm run check` + `npm run db:verify` والتحكم السلبي الثلاثي + `npm run build` + `auth-boundary-smoke.mjs` يجب أن تنجح كلها على **أحدث commit**. تحليل Patch كامل بمرور نقدي منفصل مع مقارنة المتطلبات.

## حدود الأمان

- لا حماية فعلية لجلسة مالك عبر Supabase بعد. كل المسارات المذكورة تظل **مرفوضة للجميع** حتى مع وجود متغيرات عامة في البيئة؛ لا تدعي أن المالك مسجّل.
- هذه حراسة أولية وليست بديلًا عن فحص الصلاحية داخل أي Server Action / API / RPC؛ عند إضافة عمليات دائمة يجب تطبيق التحقق من الخادم والمالك لكل واحدة.
- كل مستخدم، بما فيه المالك، لا يستطيع الدخول للواجهات الدائمة حتى إكمال المرحلة التالية؛ هذا مقصود ومحافظ.
- `/demo/*` لا يقرأ شيئًا من Supabase، ولا يُحفظ مال حقيقي، ولا توجد مفاتيح أو بيانات اعتماد في التعديل.
- لا تطبيق SQL جديد، لا حسابات/دفعات/نسخ، لا نشر أو مشروع سحابي أو تعديل بيانات إنتاج.

## مراجعة نقدية وتسليم

**قيد الفحص عند الإنشاء:** لا تُعد المهمة مقبولة قبل قراءة diff كاملة ثم إثبات تشغيل CI؛ نتائج CI وأي عيوب/إصلاحات إضافية تُسجل في ملحق H039 لاحقًا. المراجع هو نفس المساعد في مرور منفصل؛ لا يدّعي مراجعة شخص آخر.

**ما بعد H039:** تركيب حزم Supabase بنسخ مقفلة، وعملاء Browser/Server وProxy `getClaims()`، وصفحات الدخول/الخروج/الاسترجاع مع تحقق حقيقي على مشروع **اختبار**. لا يُفتح مسار دفع أو مال حقيقي على أساس صفحة login الوصفية.

## مرور نقدي ثانٍ — فجوة اكتُشفت قبل الدمج

- **الملاحظة:** أول نسخة من `proxy.ts` استخدمت قائمة أسماء مسارات محددة؛ هذا يجعل إضافة `/dashboard` أو أي endpoint جديد لاحقًا ممكنة دون حماية مؤقتة بالخطأ. كانت الفحوص موجودة للمسارات المعروفة فقط.
- **الإصلاح:** جعل `matcher` عامًا `/:path*` واستخدام قائمة سماح ضيقة وواضحة للصفحات العامة (`/`، `/login`، `/demo/*`) والأصول الثابتة المعروفة (`/_next/*`، `/fonts/*`، `/favicon.svg`). **الافتراضي منع أي مسار غير معروف** حتى عند ظهور متغيرات بيئة أو صفحات جديدة.
- **اختبار منع العودة:** توسعة `tools/auth-boundary-smoke.mjs` إلى ١٢ طلب GET ممنوعًا، و٦ طلبات POST مرفوضة (منها `POST /demo/trips`)، والتأكد من استجابة `200` لملفات CSS والأيقونة والصفحات التجريبية، ومن سلامة تحويل المسار `next` إلى مسار داخلي.
- **حدود هذا المرور:** الاعتماد على Proxy وحدها لا يصح لحماية Server Actions الحقيقية عند بدء الحفظ؛ هذه الطبقات ما زالت غير منفذة ويجب رفض الوصول على مستوى كل API وRPC في المرحلة التالية.
- **قيد الاعتماد:** التعديل الأخير **يحتاج نتيجة CI على أحدث SHA**. المراجع هنا نفس المساعد في مرور منفصل، لا Agent أو شخص ثانٍ.

**ملاحظة مراجعة ثانية حول الأصول:** السماح بـ`/fonts/*`/`/favicon.svg` يقتصر على GET/HEAD فقط؛ كان الاستثناء الأصلي يسبق فحص نوع الطلب. أُغلق هذا المسار، وأُضيف اختبار POST على الخط والأيقونة مع توقع 503؛ بذلك يصل فحص POST إلى ٦ حالات. لا سماح بكتابة لأي مسار دون Auth حقيقي.
