# H047 / T08.1 — قاعدة الدفعات فقط

## قرارات ومراجع
- D15=أ معتمد: شغل نفس اليوم يسبق الدفع. D16 (فحص التواريخ الوسيطة) **غير محسوم** رغم تصريح المستخدم أن البيانات الحالية تجريبية؛ لا يجوز افتراضه.
- D02: الدفعة بتاريخها الفعلي؛ ربطها بنقلة **وصفي فقط** ولا يخصص مبلغًا منقولًا أو يؤثر على فرق الشغل. A04: حساب العربية لدى المقاول المسؤول فقط، FK مركّب إلى `vehicle_accounts`.

## التنفيذ المنحصر
- Migration إضافية بعد A/B/C، جدول بلا رصيد مشتق مخزن؛ دفع بالقرش الصحيح الموجب، إلغاء تاريخي مع سبب ووقت، رقم إيصال نص يحفظ الصفر البادئ، نسخة، وتواريخ.
- RLS قراءة مالك فقط، لا Direct mutation بما فيه المالك، وTRUNCATE ملغي؛ كتابة فعلية يجب أن تمر لاحقًا عبر RPC مع Atomic check/A12/D13/D16 وidempotency+audit.
- رابط النقلة الوصفي يتحقق عند إدخال/تغيير المرجع في الدفعة، ولا يوجد FK مركب يمنع تعديل النقلة لاحقًا. التصحيح قد يغيّر الحساب الذي تتبعه الرحلة؛ المرجع يبقى تاريخيًا دون خصم لأي حساب آخر.
- SQL tests: 25 checks تشمل متانة القيم والمفاتيح والحسابات والتعليق/الرفض والصلاحيات؛ suites A/B/C والضوابط السلبية كما هي.

## حدود الاعتماد
- تجربة PostgreSQL معزولة ليست Supabase Auth حقيقيًا، ولا تعني إكمال T08.1 الإنتاجية أو T08.2: لا create/update/cancel payment RPC ولا حفظ واجهة ولا فحص مالي حاسم. D16 مفتوح. لا secrets أو نشر.
- مراجعة نقدية ثانية تتم على Diff بعد التنفيذ؛ رقم CI النهائي يُوثق على PR دون commit توثيق إضافي إن لم يوجد عيب حقيقي.
