# H044 / UI-BASE-01B — تقرير تنفيذ ومراجعة نقدية

التاريخ: ٥ نوفمبر ٢٠٢٦. [PR #7](https://github.com/body199-cmyk/1-mohamed/pull/7) Draft؛ لا تدمج قبل CI النهائي.

## نطاق صغير وآمن
- إضافة `isArchived` دون حذف المقاولين والعربيات أو إعادة تعيين معرفاتهم، وتعديل الأسماء/اللوحات/السائق؛ المبرر مطلوب ويظهر مع snapshot قديم وجديد في سجل in-memory.
- إخفاء السجلات المؤرشفة من الاختيارات الجديدة، ورفض مسودة نقلة مؤرشفة في `handleSubmitTrip` حتى إن كانت محددة قبل الأرشفة؛ السجلات القديمة تبقى في الذاكرة ويظل مصدر كشف المقاول متاحًا.
- واجهة إدخال/تعديل **افتتاحي نقد** بتاريخ واتجاه وقروش دقيقة لكل **زوج (عربية، مقاول مسؤول)**. هذه قيم مستقلة لا تدخل في فرق الشغل أو حركات الدفع؛ ضبط رفض تكرار الحساب بواسطة upsert لا تراكم صفين.
- الاختبارات تغطي المدخلات الخاطئة/التكرار والأرقام العربية والفارسية والقروش الكبيرة والتواريخ غير الصحيحة والأرشفة وتسجيل النقد لحسابين مختلفين وإعادة ضبط الذاكرة بعد تحديث الصفحة و360px.
- لم نعدل `supabase/migrations` أو `packages/*` أو `apps/web/src/proxy.ts`، ولا نستدعي Auth أو Vercel.

## مرور نقدي أول — أخطاء مصححة قبل القبول
1. أول GitHub Actions CI (`42039474198`) أوقف عند فحص TypeScript: `DataTab` اتسع إلى `cash` بينما `QuickAddModal` تقبل فقط مقاول/عربية. أصلحنا `quickAdd` إلى union أضيق؛ فشل CI مثبت، ولا يدّعي نجاحه.
2. أضفنا فحصًا مباشرًا لاختفاء خيار المؤرشف داخل `select` بدل Assertion سلبية ضعيفة.
3. اكتشفنا أن اختبار cash كان يحاول ملء حقل مبلغ مخفي بعد اختيار حساب جديد قبل تغيير الاتجاه؛ صُحح ترتيب الاختبار.
4. موقف D04: **لن نحرر افتتاحي فرق الشغل القديم أو ندمج افتتاحي النقد مع تاريخ النقلات** بلا قرار ومعاملة محاسبية. سجل النقد تجريبي مع audit؛ لا محرك دفع ولا سحب من بيانات حقيقية.

5. مراجعة مدخلات `BigInt` الطويلة: قيدنا طول النص قبل التحويل الرقمي، وأضفنا Unit test لرفض ١٠٠ ألف رقم فورًا بدل السماح باستهلاك غير محدود أو رمي استثناء.
