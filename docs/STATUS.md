# الحالة الحالية

آخر تحديث: ٤ نوفمبر ٢٠٢٦ — BUILD-01 (الجلسة الحالية). **الحالة: منفذة ومتحقق منها محليًا — تنتظر مراجعة المساعد.** لا يُعلن اعتماد، ولا جاهزية لأموال حقيقية.

## ما أُنجز في هذه الحزمة

| المرحلة | الحالة | الدليل |
|---|---|---|
| A — مراجعة DB-02 وتصحيح أساس القاعدة | منفذة ومتحقق منها محليًا — تنتظر مراجعة المساعد | ٦ خطوات كلها PASS على PostgreSQL معزول + اختبار تحكم سلبي ناجح |
| B — عمليات البيانات الأساسية المحمية | منفذة ومتحقق منها محليًا — تنتظر مراجعة المساعد | ٩ خطوات كلها PASS + اختبار تحكم سلبي ناجح |
| D — إعداد Supabase/Auth (الأجزاء المستقلة فقط) | مكتوبة ولم تُختبر · متوقفة بسبب عائق موضح | `.env.example`، `config.ts`، [SUPABASE_AUTH_SETUP](SUPABASE_AUTH_SETUP.md) |
| C / E / F / G | لم تبدأ بعد | — |

- `npm run db:verify` ⇒ كل الخطوات PASS؛ `npm run check` و`npm run build` ⇒ ناجحان، ومسارات `/demo/*` سليمة.
- التفاصيل الكاملة والعيوب والأوامر: [BUILD_01_REPORT](BUILD_01_REPORT.md). التسليم التاريخي: [HANDOFF_LOG](HANDOFF_LOG.md#h037).
- **الحفظ الدائم غير متاح للاستخدام الفعلي:** لا يوجد Supabase Auth حقيقي ولا بيئة محلية بها GoTrue/PostgREST. المعاينة `/demo/*` مستقلة بالذاكرة كما هي.

## المهمة التالية (نقطة الاستئناف)

**المرحلة C — `DB-03-TRIPS`:** جدول النقلات وعمليات الإنشاء/التعديل/الإلغاء/القراءة، ملتزمة بـ[ACCOUNTING_RULES](ACCOUNTING_RULES.md) ومقارنة بنتائج `@ledger/accounting`، مع الاختبارات على نفس القاعدة المعزولة. لا دفعات، ولا اعتماد D15/D16.

العائق المفتوح بالتوازي: تثبيت `@supabase/ssr@0.12.7` و`@supabase/supabase-js@2.119.0` وتوفير بيئة Supabase محلية لاختبار الدخول الحقيقي (يحتاج إذنًا بإضافة اعتمادية وقت تشغيل).

## التشغيل والمراجع

من جذر المشروع: `npm run dev` للمعاينة، `npm run build` ثم `npm run start` للمعاينة المحلية، و`npm run db:verify` للتحقق المعزول.

[تسجيل النقلات](http://127.0.0.1:3000/demo/trips) · [كشف المقاول والتصدير](http://127.0.0.1:3000/demo/contractors).

D15 وD16 ما زالا مفتوحين لقرار المستخدم؛ لم يُعتمدا في هذه الحزمة. التفاصيل التاريخية محفوظة في [H036](HANDOFF_LOG.md#h036) وتقرير [DB_02_VERIFICATION](DB_02_VERIFICATION.md).
