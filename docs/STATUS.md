## نقطة العمل التالية — AUTH-01/REAL-INTEGRATION

هذه هي **الخطوة التالية غير المنفذة**، وليست تكرار H038/H039. قبل تغيير Proxy المؤقتة أو فتح أي كتابة مالية:

1. تثبيت `@supabase/ssr` و`@supabase/supabase-js` بنسخ محددة متوافقة، مع تحديث `package-lock.json` واختبار `npm ci`؛ لا تغييرات اعتماديات واسعة أو أسرار في GitHub.
2. إعداد **مشروع Supabase اختباري معزول** (ليس بيانات إنتاج)، والتحقق من عمل GoTrue/PostgREST والحساب المالك، وملفات Browser/Server/Proxy الرسمية لـNext.js 16 والتحقق بـ`getClaims()` **على الخادم**.
3. تنفيذ مسار دخول/خروج/استرجاع فعلي مع حماية المستخدم المسجل غير المالك والجلسات المنتهية وجميع RPC/Server Actions؛ تجارب HTTP/E2E فعلية مع أدلة قابلة للمراجعة.
4. مراجعة نقدية منفصلة بعد التنفيذ، توثيق النتائج والحالات غير المختبرة، ثم PR ودمج **فقط** إن لم توجد عيوب مانعة.

**مانع البيئة الحالي:** لا تتوفر في المشروع بيئة Supabase Auth منفصلة أو دليل تفعيلها. **يمكن** كتابة مواصفات واختبارات معزولة، لكن **لا** يُعلن نجاح دخول/حفظ دائم قبل توفر الاختبار الحقيقي.

**D15/D16** يخصان سياسة الدفعات فقط وما زالا ينتظران قرار المستخدم؛ لا يعطلان العمل المستقل في Auth.
