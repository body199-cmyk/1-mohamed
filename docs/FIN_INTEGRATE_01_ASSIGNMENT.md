# FIN-INTEGRATE-01 — تكليف المنفذ

## قرار المنسق ونقطة البداية
PR #44 مدموج في main عند 605656e3e061d5c30c71b5c13a07db6c7dfd3a89. اعتمد المنسق FIN-07 تقنيًا ضمن نطاق المعاينة: تجميع دقيق يتجاوز حد الحركة الفردية مع بقاء حدود التخزين، بعد إصلاح BUG-015 وCI ناجح 43093956983 على 66f4f94. ليس اعتماد إنتاج أو تزامن حقيقي. المحلي حُدث fast-forward بلا تعارض.

## الهدف والنطاق
تجهيز FIN-04 ثم FIN-05 معًا كحزمة مترابطة على فرع جديد من أحدث main، باستخدام الشغل الموجود في PR #45 و#46، دون إعادة كتابة الإصلاحات أو دمجهما مباشرة من أساس قديم.
الملفات: migration واختبار FIN-04، migration واختبار FIN-05، tools/db-verify.mjs، ووثائق المهمة فقط. لا واجهة أو حسابات أخرى أو stage3.

## خطوات المنفذ
1. اجلب الريموت وافحص النظافة. أنشئ worktree/فرع codex/fin04-fin05-integration من أحدث main وسجل SHA. لا تعمل على main مباشرة.
2. اقرأ الفروق الحالية لـPR #45 ثم #46. انقل إضافاتهما المقصودة دون استبدال tools/db-verify.mjs بالكامل؛ حافظ على FIN-01/02 وFIN-07 وجميع الفحوص الموجودة.
3. أضف حالة FIN-04 الناقصة: دفعة غير ملغاة قبل تاريخ الافتتاحي المقترح تمنع إنشاء الافتتاحي، مع عدم بقاء صف أو تدقيق أو مفتاح تكرار بعد الرفض. اعزل الحالة بحيث لا تكون نقلة أقدم هي سبب الرفض بدل الدفعة. اختبر الحد المسموح في اليوم نفسه والحساب المسؤول الآخر.
4. اعزل بيانات اختبارات FIN-04/05 بمعرفات وحسابات خاصة. اختبارات FIN-05 القديمة تتوقع أرصدة V_H48_A وV_H48_B بينما اختبارات FIN-01/02 وFIN-07 في main تغير هذه الحسابات؛ لا تبدل أرقام التوقع فقط ولا تحذف الفحوص لتخفي التداخل. ابنِ بيانات اختبار مستقلة واحسب توقعاتها من سيناريو صريح.
5. تحقق من رصيد بداية يوم الافتتاحي ونهايته، فترة لاحقة، فترة تاريخية مقابل الرصيد الحالي، عدم عد الافتتاحي مرتين، فصل المسؤولين، وتوافق القراءة القديمة دون فترة.
6. راجع القفل وترتيب الكتابة والصلاحيات في مسارات SQL. PGlite ليس إثبات تزامن جلستين: سجل هذا القيد، ولا تتصل بإنتاج أو Supabase خارجي. لا تدع حماية سباق غير مختبرة.
7. شغل npm ci ثم SQL والضوابط السلبية والفحوص الكاملة المناسبة. لا تعدل migrations المطبقة سابقًا؛ إن احتاجت migration المرشحة تعديلًا فثبت أنها غير مطبقة في بيئة دائمة أولًا، وإلا أضف تصحيحًا جديدًا.
8. حدّث STATUS باختصار: #44 مدموج وFIN-07 معتمد ضمن نطاقه، وهذه المهمة قيد التحقق. حدّث TASKS/SUBTASKS/CODE_MAP/HANDOFF عند الحاجة، وأضف docs/FIN_INTEGRATE_01_REPORT.md بالملفات والأدلة والقيود. حافظ على التاريخ ولا تعلن دمجًا لم يحدث.
9. راجع الفروق مرورًا ثانيًا ثم commit وpush بعد كل خطوة قابلة للمراجعة. افتح PR إلى main، وشغل CI على الرأس النهائي. لا force push ولا دمج ولا إغلاق PR #45/#46؛ المنسق يحسمهما بعد قبول البديل.

## القبول والتسليم
كل فحوص main باقية وناجحة، واختبارات مستقلة للدفعة السابقة والافتتاحي والفترات، لا تغيير للبيانات التاريخية أو تاريخ الدفع، لا سقوط فحص من db-verify. سلّم رابط PR والتقرير وSHA وCI وملخص العوائق. توقف عند قرار تجاري غير محسوم دون توسيع المهمة.
