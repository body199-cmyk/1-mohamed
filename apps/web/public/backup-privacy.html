Backup privacy policy

What the service accesses

The project operator authorizes Google Drive access for the backup job. It requests file-level access (drive.file) to create and manage the folders and files it uses. It uses file names, paths and verification information, plus the encrypted file contents when checking or recovering a backup. It does not request full access to the operator’s Drive.

How data is used and protected

The project uses this access to upload, check, recover and, when retention is enabled, remove older managed backups. A backup can contain ledger records and account recovery data. The job encrypts that data before upload. The encrypted archives are stored in the operator’s Drive and the operator keeps the decryption key separately.

GitHub Actions runs the backup and stores the Google authorization as a protected secret. Google Drive stores the encrypted files. The service does not sell Google user data or use it for advertising. The project’s use of Google user data follows the Google API Services User Data Policy, including the Limited Use requirements.

Retention and removal

The daily backup policy keeps one copy per Cairo calendar day for the latest 30 calendar days. Once automatic retention is enabled, it removes only managed archives outside that window after a new backup has been verified. Test copies created during setup may need to be removed separately by the operator.

The operator can revoke the connection in Google Account connections and delete the remaining copies from Drive. Revoking access stops the job from using Drive; it does not delete existing files.

Contact

For questions about backup data or removal, contact the project operator or use the support email shown on the Google consent screen.
